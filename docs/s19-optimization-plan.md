# S19 规划：语言语义实验室、报告边界修复与可演示性增强

状态：实施完成，等待主窗口审查。S19 从已审查本地 `main` 基线 `c966f97096fd590a77176c9b18f8f45fee5fed31` 创建 `stage/s19-language-lab-robustness`；阶段报告见 [S19 执行报告](s19-language-lab.md)。S12 继续作为最后收尾且未开始。

## 为什么做这一轮

教师评分中，解释器实现、黑盒测试、人/AI 指南合计 60 分；Agent 编写的 246 行 LWT 日志分析器及 S18 工作台提供 30 分应用证据。当前应用已能展示“用 LWT 解决问题”，下一轮最有价值的创新是让教师能**亲自运行小型 LWT 程序，先观察源码和语义提示，再看到真实 CLI 的 stdout、stderr 与退出码**。这补强对语言规则和实现细节的可解释性，同时保留日志分析器作为唯一主要 LWT 应用，不把 Python 图形程序冒充 LWT 程序。

## 优先级

1. **P0 修复 S18 真实缺陷**：报告解析只用协议 LF 分行，保留 U+0085/U+2028/U+2029、VT/FF 等合法字段字符；用真实 LWT CLI 输出和纯解析测试确认。保持固定标题、字段、计数、顺序和截断校验。详见 [S18 主窗口复核](s18-main-review.md)。
2. **P0 补关键 GUI 证据**：在可操作桌面完成 S18 工作台组合过滤、原始报告、零匹配、错误恢复、文件选择和窗口缩放；若同机输入干扰，停止归因并如实报告。不要用 Tk 几何检查替代目视/点击。
3. **P1 建立独立的只读“LWT 语义实验室”**：标准库 Tkinter，六个固定示例覆盖分支/循环、函数/递归、数组/record/`each` 浅快照、文本内置函数与 CLI 参数、stdin 和运行时错误定位。显示真实 LWT 源码、规范对应点、公开 CLI argv、工作目录、stdin、stdout/stderr/退出码及预期结论。运行放后台、有限超时，主线程更新界面；CLI 不可用时显示可读错误。当前 GUI 人工操作未验证，报告不以无头测试替代。
4. **P1 保持演示边界清晰**：实验室是 Python 教学前端，S10 的 LWT 日志分析器仍是课程 ≥200 行应用证据；Snake 仍是独立 Python 附加演示。更新应用说明、开发指南和 Agent 开发记录，提供可重复的约三分钟语言特性演示。最终 PPT 和新克隆验收留给 S12。

## 完成门槛

- U+2028 真实 CLI 输入不再被工作台误拒绝；常见 Unicode 分隔字符有定向回归，同时损坏报告仍被拒绝。
- 六个固定示例均通过真实 `python -m lwt` 路径运行，结果与各自记录的预期一致；正常与错误示例覆盖 stdout、stderr 和退出码，不调用 Python `eval/exec` 执行 LWT。
- 原 194/194 黑盒、256 项基线 unittest、25 项 S10 应用测试、246 行 LWT 统计以及完整性检查仍通过。任何新增测试只计实际完成数，不用数量代替语义覆盖。
- 记录可归因 GUI 操作与未验证项；保护 S10 并发和 S11 性能原始证据，不重跑其生成器；阶段分支只提交待审，不合并或推送。
