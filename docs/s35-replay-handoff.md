## 4. 先冻结录制契约

新建独立 replay 格式说明，明确 schema_version、LWS1 protocol_version、引擎源码摘要算法、棋盘/seed、按执行顺序排列的记录，以及可选的分支来源信息。先写小而完整的有效和无效样例，再编码。

记录由 bridge 实际完成的请求/响应事务生成，包括 INIT 和消耗序号的 CommandRejected；记录实际 LWT 返回的完整、已验证状态或 ERR。不要记录未送出的键盘事件充当命令，也不要只记录 GUI 最终显示的快照。被 UI 丢弃的旧显示响应可能对应已执行命令，不能从记录中漏掉。超时、半帧或损坏响应不伪造成功事务，仅保留此前完整前缀及中断原因。

可采用结构化 command/args＋完整响应对象，或者严格规范化的请求/响应帧；选一种作为唯一事实来源，避免两套内容可能矛盾。序号规则复用 S34。记录范围是本应用 bridge 可产生的命令，不必支持任意畸形协议流。传输关闭用 QUIT 的收尾行为单独规定：建议不纳入可接管前缀，验证结束仍正常关闭并检查退出；不要悄悄改动已录事务。

源码身份不能仅依赖 Git SHA，脏工作树也要可识别。可使用明确版本的源码规范化 SHA-256（严格 UTF-8、仅去掉开头一个 BOM、CRLF/CR→LF，其他内容不改），避免 Windows/Linux 换行造成假不兼容。保存摘要算法名并测试规范化边界。记录 Git/Python 环境仅作溯源，不声称摘要是防作弊签名。载入只执行仓库固定可信 game.lwt，绝不执行记录文件提供的 source_path、命令行或内嵌源码。源码/协议不兼容默认拒绝，给出可读原因。

## 5. 录制与文件保存

- 一个引擎会话从 INIT 开始形成自包含记录；RESET 保留为事务，不能丢弃随机状态重置事实。
- 保存当前完整前缀应通过 worker 的明确一致性边界取得不可变副本。保存文件对话框若引发自动 PAUSE，必须记录真实 PAUSE 事务，而不是假设它不存在。
- 文件采用 UTF-8 JSON，只用标准库；严格检查字段、类型、版本、序号和范围。整数验证排除 bool；拒绝重复键、NaN/Infinity、非法 UTF-8、超大整数和不符合契约的未知字段。
- 初版设置明确的有界策略，例如最多 5000 笔事务、16 MiB 文件；在计划中说明取值，集中定义常量。读取先限字节再解析，解析后限结构和条数。达到录制上限时停止追加并明确提示“仅保存到第 N 条”，允许导出完整前缀，不能无限占用内存或假称整局已保存。
- 同目录临时文件写完后替换目标；保存失败保留原文件，清理仅限本次创建的临时文件。覆盖现有用户文件通过明确的保存交互处理，不默认覆盖其他项目文件。不宣称此操作能保证任何断电场景的数据持久性。
- 中文、空格路径、只读/不可写目标、取消保存、JSON 损坏均有可读反馈。不要把用户对局自动加入 Git，也不要自动上传。

## 6. 独立验证与回放服务

新增无 Tk 的公共验证入口，建议 `python -m app.lwt_snake.replay --verify <file>`；冻结实际命令、stdout/stderr 和应用工具退出码（例如 0=一致、2=文件/契约/兼容性错误、3=执行失败或响应分歧，注明不是改变 LWT CLI）。

验证必须启动新的真实公开 LWT CLI 子进程，按录制顺序重发命令，逐笔比较完整响应；不能只检查哈希、播放文件中的坐标或使用 Python Snake 模型代替执行。返回验证笔数与结果，首个分歧报告事务索引、序号、命令、差异字段和有界预期/实际值。意料中的 ERR 同样比较且继续，意外 ERR 应判失败。结束时核验正常退出并回收进程。

每请求超时之外，还要有整次验证/重建的总时限和取消机制。验证失败、取消、EOF、启动异常不能写“验证通过”。默认拒绝不兼容版本；不要用自动修改文件来消除分歧。

## 7. 可交互复盘与接管

在现有 LWT Snake 入口内提供清晰的实时/回放模式，复用绘图，不再创建新的游戏产品。

- 保存本局、载入记录、验证进度、命令位置、上一条/下一条、播放/暂停、有限速度档位、返回实时游戏、从此处接管。
- 回放索引按事务定义，明确 TURN 不一定移动、PAUSE/RESET/ERR 也会占位置；展示当前命令和得分。可提供跳转到指定位置，不要求复杂滑轨或完整视频时间线。
- 只有通过真实 LWT 验证产生的快照才能标为已验证并用于复盘。允许缓存这些快照供后退展示，但接管必须在新引擎上从 INIT 重放至该前缀，重新确认结果后才允许用户操作。
- 回放期间停止本地自动 TICK 和实时方向输入；视觉暂停不等于向 LWT 发送 PAUSE。特别注意 PAUSE 会清除 pending_direction，不能为了展示静止而改变待接管状态。
- READY 前缀可接管后开始；RUNNING 前缀在用户明确接管时恢复时钟；PAUSED 前缀保留暂停，等待用户继续；GAME_OVER/WON 可回放但不直接接管到“运行中”，允许返回较早前缀或正常 RESET 开新局。
- 子对局包含父对局所选前缀和后续新事务，独立文件即可重放；来源摘要/前缀索引只作说明，不要求父文件仍在原路径。不要覆盖原局。接管产生的协议序号必须连续。
- 处理连续载入、取消验证、旧 worker 回复、请求中关闭及异常重试，明确 generation 生命周期。一次活动引擎所有权清晰，切换前回收旧进程；重建时 UI 可取消且不阻塞 Tk。
- 界面文字面向玩家；协议/摘要信息放到详情，不挤占主要操作。沿用主题，支持键盘焦点和已有最小尺寸；不把自动控件测试写成人工视觉通过。

## 8. 测试必须证明真实能力

优先测试高风险边界，不为凑数量拆分断言：

1. 时钟回归：连续同方向输入、拒绝转向、到期 busy、慢响应、暂停/复位/关闭、旧回复均不能破坏时钟和串行约束。
2. 文件契约：合法最小记录、空/截断/重复键/错版本/非整数/异常大文件/乱序/缺事务/错响应；中文路径；保存中失败不破坏已有文件。
3. 真实 LWT 往返：新进程录制再验证，完整响应一致；至少覆盖增长、拒绝转向、同 tick 多 TURN、PAUSE 清除 pending、RESET、撞墙/撞身、4×1 获胜。
4. 篡改一个合法范围内的响应字段，即使重新算摘要也必须在真实重放中出现分歧；随机种子或命令前缀改动也不能仅凭文件自述通过。
5. 接管等价性：同一命令前缀＋相同后续命令，在原引擎与新重建引擎逐步一致；选含 pending TURN 及多次随机食物选择的前缀，不只测初始棋盘。不同后续命令形成独立分支，原局未改且子局再次验证通过。
6. UI 真实 Tk 控件/事件：保存、载入、验证、单步、播放暂停、接管、返回实时、失败恢复及请求中关闭。仅在文件对话框等边界注入；主要验证路径仍走真实子进程。
7. 故障：超时、损坏响应、取消、加载第二个记录覆盖旧任务、达到上限；无残留 owned worker/进程，无越界队列或误报成功。
