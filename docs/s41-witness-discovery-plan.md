# S41 派发规划：Agent 策略差异自动发现与可复现反馈

状态：**仅规划，尚未实施**。S40 已通过[主窗口复核](s40-main-review.md)并快进进入本地 `main`；执行窗口开工前仍要核对远端及工作区真实状态。S41 是 S12 最终验收前最后一个有界功能阶段。

## 价值与证据

[作业原文](../大作业内容.md)的 Agent 编写 LWT 应用占 30 分，开发指南占 20 分。S39 让 Agent 能编写新策略，S40 能验证人工选定的同局面一步分歧。S41 应让系统**自动从受控、双层验真的对局中找到有解释价值的方向分歧**，产出 Agent 可据此修改策略的反馈和 S40 可重验的具体证据。答辩可以从一份 LWT 策略源码出发，运行检查和擂台，自动定位分歧，再打开一条按固定顺序选出的已验观察前缀，展示一步结果及验证。

参考 [Robocode Tank Royale 调试指南](https://github.com/robocode-dev/tank-royale/blob/main/docs/DEBUGGING-GUIDE.md)对策略意图与对局录制分层诊断的做法，以及 Zeller/Hildebrandt 的[原始最小化研究](https://issta16.cispa.saarland/papers/tse2002/)对小型可复现反例的价值。本项目**只宣称给定有界清单中按规定顺序找到的最早分歧**；策略可能依赖先前观察，不能任意删前缀，也不能称结果为全局最小反例或策略优劣证明。

## 先冻结搜索语义

- 输入是 S39 v3 结果、**显式**可信 catalog、一个参考策略 ID 和一至两个挑战者 ID；所有 ID 必须属于结果中的已绑定源码。先运行完整 `arena.verify`，只扫描正常完成且 `game_verified`、`policy_verified` 均为真的参考策略对局。v1/v2、失败局、目录或源码变化应明确拒绝或按冻结规则计为不可扫描，不能悄悄降级。
- 搜索顺序固定为 seed 数值升序、参考对局、咨询步数升序、挑战者 ID 字典序。对每条参考对局，在新游戏进程恢复真实状态序列；参考及挑战者各用独立长驻 LWT 策略进程，按序接收相同观察，不为每个步数重启策略。比较 **MOVE 方向或 NONE/TRAPPED**，原因 `FOOD/SPACE` 不同但方向相同可作为说明，不算“方向分歧”。
- 只在配置的最多 32 次咨询内搜索；限定策略数、seed/对局数、每请求及总硬截止时间。找到首个合格分歧即停止，并调用 S40 的真实分析/验真能力生成单步分支证据。无分歧是正常且可报告的结果：明确 `found=false`、已扫描多少条观察和搜索边界，不伪造见证，也不把“未发现”解释成策略等价。
- “最早”仅针对本次输入、排序和检查上限。若搜索因某一候选进程失败，应给出失败并停止，不能把未完成扫描写成 `found=false`。每种策略的协议序号、源码摘要和查询前状态均须核对。

## 可用命令和产物

建议新增独立 CLI，例如：

```powershell
python -m app.lwt_snake.witness --result reports/s39-demo/result.json --catalog app/lwt_snake/strategies/strategy-catalog.json --reference baseline --challengers bfs,mobility-lookahead --max-observations 32 --output NEW_DIR
python -m app.lwt_snake.witness --verify NEW_DIR --catalog app/lwt_snake/strategies/strategy-catalog.json
```

`--output` 只接受新目录。产物包括严格版本化的 `witness.json`、机器可读的 Agent 反馈、简短人类报告；找到分歧时嵌套/引用 S40 的 `analysis.json` 和三条一步分支，未找到时没有伪造分支。反馈须写明原 LWT 策略、输入哈希、case/step、同轨迹语义、参考与挑战者响应、扫描范围，以及“可尝试改进”的中性问题；不要自动修改策略源码、声称哪个策略更好或宣称这一步得分预示整局表现。所有 JSON 严格拒绝重复键、未知字段、异常数字、路径穿越/链接、哈希或版本不符；`--verify` 不信自述的 `verified/found`，需重新运行搜索并复验 S40 证据。相同输入的核心逻辑 JSON 应字节一致。

将 S40 只读 Tk 查看器扩展为**显式加载本地 S41 见证目录**，能展示搜索顺序、找到的 case/step、候选响应及 S40 一步证据；由后台线程做真实验真，主线程更新 Tk。固定演示入口保持可用。无 GUI 的 CLI/报告必须足够完成答辩演示。不要增加第三方 GUI 依赖或在线服务。
