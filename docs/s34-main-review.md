## 结论

LWT 源码确实负责蛇身、食物、随机数、得分与状态转移；Python 负责协议、子进程、事件和绘图。固定命令重放及多数定向测试支持这一职责划分。但是独立复核发现一个可重复的游戏时钟缺陷，另有一个失焦测试在整组运行失败、单独运行通过。不能将执行窗口的历史全绿结果视为本轮审查通过。

### R34-01：转向输入可以无限推迟移动（P2，必须修复）

`app/lwt_snake/ui.py` 中 `send()` 对所有命令执行 `cancel_tick()`；收到任何响应后，`poll()` 调用 `schedule_tick()`，从响应时刻重新等待完整的 `tick_ms`。因此持续同方向输入也会不断取消移动计时器。控制响应和游戏时钟耦合，正常按键重复就能让 RUNNING 中的蛇不移动。

本轮在隐藏 Tk 根窗口、真实 LWT 子进程上复现：设置 `tick_ms=250`，START 后每约 50 ms 发送一次 `TURN R`，持续 1.217 秒、共 21 次；蛇头从 `(12, 9)` 到 `(12, 9)`，phase 仍为 RUNNING。停止转向输入后，蛇头才到 `(13, 9)`。最后 worker 已退出，子进程返回 0。

复现核心流程：等待 INIT → START 响应 → 记录蛇头 → 在超过四个 tick 周期内重复发送 TURN R，每次等待响应并泵送 Tk 事件 → 比较蛇头 → 停止输入等待下一次移动。整个过程不计算 Python 蛇规则，也不需要人工键鼠。

修复应使 TURN 的响应不重设移动截止时间；请求串行、到期移动不被持续输入饿死；慢响应不积压无限 TICK。仅删掉 `cancel_tick()` 不足以证明正确：当前 `tick()` 在 busy 时可能丢弃到期移动。需要覆盖 busy、暂停、复位、错误及关闭的统一调度规则。

### R34-02：外部失焦测试存在未解释的不稳定性（P2，必须定位）

本轮命令 `python -m unittest discover -s tests -p 'test_lwt_snake*.py' -v` 返回 1：13 项中 12 项通过，`test_real_buttons_keys_focus_reset_and_close` 在第 64 行等待 PAUSED 超时。随后单独运行该方法返回 0，1 项通过（0.782 秒）。

现有测试创建 `Toplevel` 后直接 `focus_force()`，未先确认窗口映射和实际焦点归属。此处是调查线索，不是已经证明的根因。下一窗口须记录窗口映射、`focus_displayof()`、事件先后和请求状态，区分测试前置条件不足、桌面干扰与产品失焦处理问题。不得靠延长等待、自动重试直至成功、删除失焦断言或伪装 skip 解决。

## 连续转向与生命周期审阅

- 当前协议明文允许同一 TICK 前最后一个合法 TURN 生效，反向校验相对于最后接受的方向。因此 R→U→L 后 TICK 撞身是既定规则，且已有固定用例。它不是本轮新发现的实现偏差；本阶段不要悄悄改成转向队列或每步只接受一次。
- `EngineWorker` 只有一个串行请求路径；bridge 有 stdout/stderr 读取线程、有界响应队列、超时与关闭回收。定向运行中的故障测试通过，支持已测场景的回收结论，不构成全部并发时序的证明。
- GUI 会丢弃旧 request_id 的显示结果；将来录制必须发生在实际请求/响应边界，不能仅记录 UI 展示过的快照，否则 RESET/PAUSE 替换期间会漏掉已经执行的命令。
- `game.direction`、`pending_direction`、`has_pending`、随机数状态均影响后续结果。显示快照不包含全部隐藏状态。保存和继续应通过命令前缀重执行重建，不应从坐标猜测内部状态。
