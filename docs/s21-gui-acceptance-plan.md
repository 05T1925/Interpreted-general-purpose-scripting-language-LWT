# S21 规划：答辩应用桌面验收与缺陷闭环

状态：待派发。S20 已通过主窗口审查并合入本地 `main`；S21 是最终交付前最后一次 GUI 人工验收阶段。完成并审查 S21 后进入 S12。S21 不新增产品功能；重点是用真实操作确认现有演示在答辩环境中是否可用，并修复能稳定复现的阻断问题。

## 为什么下一步以验收为主

S20 已补上启动退出码和“预测—运行—解释”学习流程；目前缺少的关键证据是应用窗口能否在真实桌面里正确布局、接受输入、显示状态和从错误恢复。继续新建小游戏、仪表盘或功能模块不会补齐这项证据，也容易让答辩范围发散。课程 30 分应用分值来自 Agent 编写的 LWT 应用本身；Python/Tkinter 前端只能作为讲解和展示辅助，不能替代 `app/log_report.lwt`。

## 验收范围

### A. 语义实验室

- 启动窗口，确认标题、Python 教学前端声明、六主题列表、中文显示和窗口可缩放。
- 逐主题切换，确认源码和预测题同步、源码不可编辑、长内容能滚动。
- 至少实际完成一题正确预测和一题错误预测：选择、提交、运行、观察预测反馈与真实 CLI 输出/退出码/解释。
- 实跑 stdin 示例和 RuntimeError 示例，核对输入、stderr、位置及退出码；重置后再次作答。
- 复核 Enter/Tab 等键盘操作、运行中状态、关闭窗口、运行失败后恢复。

### B. 日志分析工作台和五题挑战

- 从 GUI 执行 `WARN + retry + top=2`，对照显示的查询条件、结果、CLI argv 和同一次执行的完整原始报告。
- 实测更改条件后清除旧结果、零匹配、无效路径、错误后恢复、带空格/Unicode 的文件路径和可用窗口尺寸。
- 在五题挑战完成第五题，观察反馈/进度/最终结果并重开；检查 Enter 提交。

### C. 贪吃蛇

- 实际操作方向键和 WASD、Space 暂停/继续、R 重开、终态“再来一局”、失焦暂停/恢复。
- 检查键盘焦点、按钮操作、窗口缩放和结束/胜利画面。若输入法拦截快捷键，记录观察及按钮后退方式。

## 执行规则

- 先确认当前窗口、桌面自动化接口和输入归属；仅在操作能明确落到目标窗口时继续。出现其他用户输入、覆盖窗口或无法归因时立即停止自动输入，保留事实和剩余清单。
- 尝试使用稳定可操作的 Windows 桌面。必要时先确认目标 Python、Tkinter 版本、屏幕分辨率和缩放；不要为了测试安装不必要依赖或更改系统设置。
- 截图只作为真实取得的辅助证据，不能由启动窗口、非零句柄、代码审阅、几何计算或无头测试代替操作记录。截图中有个人信息时不要保存或提交。
- 记录每项的具体操作、看到的状态、预期与实际差异、环境、是否由本人操作可归因。分别列出人工实测、CLI/自动测试支持、代码审阅和未验证。
- 若发现问题，先稳定复现；只做范围内最小修复，并加可自动验证的回归。桌面交互无法自动复现时，记录人工复现步骤和前后观察，不夸大自动化证据。
- 若桌面仍不可用，完成必要的自动检查和代码审阅，明确列出环境限制；提交阶段报告后停止，不另行创建后续应用阶段。主窗口审查后进入 S12，并将 GUI 手工复核列为最终现场演示前检查项。

## 验收与保护范围

- 不新增游戏、应用模式、联网、账户、用户脚本编辑、第三方依赖或 LWT 语法。
- 不修改 `lwt/`、正式语言规范、S8 黑盒矩阵、S10 并发原始数据或 S11 性能原始数据；不得运行会覆盖并发/性能证据的生成器。
- 若改动代码，运行全量 unittest、`python tools/run_tests.py`、完整性检查、compileall、LWT 行数和 `git diff --check`；报告真实结果。
- 保护文件须相对阶段基线逐个比较。S10 应用保持 246 行有效 LWT 和 25 项应用契约测试。
- 更新 `docs/s21-gui-acceptance.md`、`docs/agent-dev-log.md`、`project.md`、README/应用说明中必要的状态及路线图。阶段报告包含验收矩阵、改动/提交、实际测试、限制和 S12 交接。
- 阶段分支从当时已审查本地 `main` 创建，先检查状态和基线；不推送、不合并、不做 S12 的新克隆验收、最终 CI、PPT、发布或标签。

## 交接结果

以“桌面验收完成，等待主窗口审查”或“受桌面限制未能完整验收，等待主窗口审查”作为结论。交付分支、基线、提交 SHA、操作环境、逐项手测结果、必要修复、自动检查、保护文件差异及未验证项。S21 审查通过后冻结应用功能范围并进入 S12。
