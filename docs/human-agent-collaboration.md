> 对应课件第 8 章结尾两张幻灯片“我们如何与 Coding Agent 合作？Vibe Coding?”与第 3 章 3.4“必须由人主导的决策”。本文只写能在仓库里找到出处的事实。

## 0. 三种角色（不混用）

| 角色 | 是谁 | 在仓库里的叫法 |
|---|---|---|
| **本人** | 刘文涛（课程学生，仓库作者） | 用户、本人、“用户裁决” |
| **规划复核窗口（AI）** | 另一个 Agent 会话：起草阶段任务书、复核执行结果 | 主窗口、主窗口复核、主窗口裁决 |

## 4. 是不是 Vibe Coding？

**部分是，而且要说清楚是哪一部分。**

- **代码层面接近 Vibe Coding**：解释器、工具和应用的大部分代码由 Agent 生成，本人**没有逐行审查**。
- **质量不靠“读得顺”，靠可复算的证据**：401 项黑盒、19 条语义变异探针全部被判红（证明测试会红）、四格 CI（Ubuntu/Windows × Python 3.10/3.13）、规划复核窗口的复核报告，以及上表这些被复核抓出来的错误。
- **决策不交给 Agent**：推送、合并方式、版本号与标签、对外公开什么、GUI 验收、平台上传，都保留在本人这一侧（见 §2）；Agent 起草选项，本人选择。
- **审查能力有边界**：复核窗口也是 AI，它能抓到上表的错误，但不等于人工审查；GUI A–E 与教师验收仍未发生。

这对应课件第 3 章 3.4“让生成速度服从审查能力”：Agent 的产出速度很快，所以把重复检查交给自动测试与变异探针，把每个阶段的推进节奏绑定到“证据全绿 + 本人裁决”，而不是“代码看起来对”。
