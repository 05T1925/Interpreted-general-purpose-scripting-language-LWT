# S20 规划：课程演示交互与 GUI 验收收口

状态：计划阶段，尚未实施。S19 已通过主窗口审查并合入本地 `main`；下一阶段基线为 `3057df65cef0edcc82ad050462f2fa7991cd28db`。S12 仍是最终新克隆验收、PPT、演示和交付阶段。

## 目标

在进入 S12 前做最后一轮有边界的教学体验与桌面验收：修正语义实验室启动失败的退出码；为现有 LWT 语义实验室增加真正可参与的“先预测、再运行、最后解释”流程；在有可归因输入的桌面环境复核既有 GUI。结束后冻结功能范围，转入 S12，不再无证据地追加应用功能。

这轮的教学创新是把实验室的静态“观察点”变成学生能作答的预测练习。所有示例仍调用真实 LWT CLI；Python 前端只对照固定教学选项和 CLI 原始结果，不解析或模拟 LWT 程序。

## 优先级

1. **P0 启动契约修复：** Tkinter 缺失或 Tcl 初始化失败时，入口向 stderr 打印清楚诊断并以非零退出码结束；增加真实子进程测试。正常可启动环境和已有无头测试继续通过。
2. **P1 GUI 实测：** 可归因操作语义实验室的案例选择、源码只读、预测提交、CLI 运行、匹配/未匹配反馈、错误案例、重试和关闭；复核工作台筛选/原始报告/零匹配/错误恢复/文件选择/缩放，日志侦探第五题结束与重开，以及 Snake 键盘、Space/R、失焦暂停恢复和重开。每项记录操作步骤及实际观察；环境不可用时诚实保留未验证。
3. **P1 预测—运行—解释：** 六个固定示例各增加有限的预测选择和简短解释。用户先选择预测，再运行真实 CLI，随后显示预测是否与预期输出一致、实际 stdout/stderr/退出码及对应语言语义解释。至少覆盖一项边界或错误行为。预测答案写在固定白名单中，并用测试确保正确选项与该示例的 `expected_stdout`/预期退出契约一致；不要在 Python 中重新解释、执行或推导 LWT。
4. **P2 可用性与文档：** 在常见笔记本分辨率下核对中文、源码长行、输出滚动、按钮状态和窗口关闭；若实际发现问题再小幅调整布局。补充一页课堂操作说明和 3–5 分钟演示脚本，说明预测、运行、观察输出和语言规则之间的联系。保持教学前端、LWT CLI 和 Agent LWT 应用的职责边界清楚。

## 完成门槛

- Tk/Tcl 不可用的 CLI 启动失败为非零退出，诊断进入 stderr；存在真实子进程断言。
- 预测互动有键盘可达的控件、清晰的未答/已答/运行中/成功/错误状态；切换示例或重跑不会显示过期预测和旧 CLI 结果。
- 六个案例仍通过公开 `python -m lwt` 执行，stdout、stderr、退出码契约稳定；现有白名单、安全边界、超时和窗口关闭逻辑不回退。
- GUI 人工操作、自动化/无头测试和未验证项分栏记录，不能互相替代。若没有可靠桌面输入环境，不以工具启动或窗口句柄宣称验收通过。
- 194 项黑盒测试、S19 基线 268 项 unittest、完整性检查、compileall、有效 LWT 行数 246 和保护文件核验通过。新增测试数量据实报告。
- 不修改 LWT 运行时、正式语义、测试矩阵、S10 并发证据、S11 性能原始数据；若 S20 没有发现明确缺陷，不运行会覆盖原始证据的生成器。
- 更新 README、应用说明、开发指南（确有需要时）、`project.md`、开发记录、阶段路线图、总/详细规划，并新增 S20 实施报告。记录 Git 分支/提交/完整 SHA、实际命令输出、桌面证据和剩余限制。

## 设计参考

- Tucker 等人在 2024 年《Learning and Instruction》发表的[编程教学预测任务研究](https://doi.org/10.1016/j.learninstruc.2023.101871)比较了预测与讲解/练习教学活动。该研究为“先预测、再运行、再解释”提供教学设计启发；本项目没有开展学习效果实验，因此不宣称 S20 能提升学习成绩。
- Python 官方 [`sys.exit`](https://docs.python.org/3/library/sys.html#sys.exit) 文档说明退出码 0 表示成功，非零表示异常终止；这是启动失败应返回非零的契约依据。
- Python 官方 [Tkinter 线程模型](https://docs.python.org/3/library/tkinter.html#threading-model)指出事件处理应快速返回，长任务宜放入其他线程或分段执行；沿用 S19 的后台 CLI、Tk 主线程绘制边界。
